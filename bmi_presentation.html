Noto'g'ri narxlar:
Ko'p o'zgaruvchili Regressiya

Uy egasi narxni "ko'z bilan" belgilaydi — bu ob'ektiv emas. Biz Multiple Linear Regression modeli orqali ma'lumotlarga asoslangan narx tavsiya qilamiz.

Model o'zgaruvchilari (Xususiyatlar)
X₁ — Xonalar soni
X₂ — Umumiy maydon (m²)
X₃ — Qavat / Jami qavatlar
X₄ — Joylashuv bahosi (0–10)
X₅ — Ta'mir darajasi (0–3)
X₆ — Metroga masofa (km)
📊 O'quv ma'lumotlari
Model so'nggi 90 kunlik tranzaksiyalar asosida o'qitiladi. PostgreSQL da saqlangan haqiqiy narxlardan β koeffitsientlar hisoblanadi.
Lineer Regressiya Formulasi
Ŷ = β₀ + β₁X₁ + β₂X₂ + ... + β₆X₆
Ŷ — bashorat qilingan narx (so'm / oy)
βj = Σ(Xⱼ − X̄ⱼ)(Y − Ȳ) Σ(Xⱼ − X̄ⱼ)²
β koeffitsientlarini hisoblash (Ordinary Least Squares)
📐 Haqiqiy misol (Yunusobod, 2 xona):
Ŷ = 120,000 ← β₀ (bazaviy narx)

Geo Qidiruv:
Haversine Formulasi

Barcha mahalliy saytlarda "menga yaqin uy" deb qidirish mumkin emas. Biz Haversine formulasi yordamida ikkita GPS nuqta orasidagi haqiqiy masofani hisoblaymiz.

Foydalanuvchi nuqtasi (lat₁, lng₁)
→
Haversine formula
→
d (km) < radius?
1
Koordinatalar farqi hisoblanadi
Δφ = φ₂ − φ₁ (kenglik farqi), Δλ = λ₂ − λ₁ (uzunlik farqi)
2
a — yordamchi son hisoblanadi
sin²(Δφ/2) + cos(φ₁)·cos(φ₂)·sin²(Δλ/2)
3
c — markaziy burchak topiladi
c = 2·arctan2(√a, √(1−a))
4
d — haqiqiy masofa (km)
d = R · c, bu yerda R = 6,371 km (Yer radiusi)
Haversine Formulasi
a = sin²(Δφ2) + cos(φ₁) · cos(φ₂) · sin²(Δλ2)
d = 2R · arcsin(√a)
R = 6,371 km (Yer radiusi) · φ = kenglik · λ = uzunlik
📐 Haqiqiy misol
Foydalanuvchi: (41.2995°N, 69.2401°E) Toshkent
Uy: (41.3111°N, 69.2799°E) Yunusobod
──────────────────────────────
Δφ = 0.0116° → 1.29 km (shimolga)
Δλ = 0.0398° → 3.21 km (sharqqa)
d ≈ 3.46 km — radiusga mosmi? ✅
❌ Avvalgi holat

✅ Mulkchi

Ishonch reyting:
Og'irlik berilgan o'rtacha

Oddiy o'rtacha (★+★+★)/3 — adolatsiz. Eski sharhlar ham yangi kabi hisoblanadi. Biz Weighted Moving Average algoritmi qo'llaymiz — yangi sharhlar muhimroq.

Rw = Σ (rᵢ × wᵢ) Σ wᵢ
rᵢ — sharh reytingi | wᵢ — vaqt og'irligi
wi = e−λ × t      λ = 0.1 (eskirish darajasi)
t — kun (bugun = 0, 30 kun oldin = 30) | e — Eyler soni ≈ 2.718
📐 Misol: 3 ta sharh
r₁=5.0, t=2 kun:   w₁ = e−0.1×2 = 0.819
r₂=3.0, t=15 kun: w₂ = e−0.1×15 = 0.223
r₃=4.0, t=30 kun: w₃ = e−0.1×30 = 0.050
──────────────────────────────────
Rw = (5×0.819 + 3×0.223 + 4×0.050) / (0.819+0.223+0.050)
     = 4.70 ← yangi yaxshi sharh ko'proq ta'sir qiladi

Aqlli Tavsiya:
Kontent o'xshashligi

Foydalanuvchi ko'rgan uyga o'xshash boshqa uylarni qanday topish mumkin? Biz Cosine Similarity algoritmi qo'llaymiz.

Har bir uy vektori sifatida ifodalanadi
Uy A = [xonalar, maydon, narx, joylashuv, ta'mir]
A = [2, 65, 650, 8.5, 3]   ← Yunusobod, 2 xona
B = [2, 70, 680, 8.0, 3]   ← Chilonzor, 2 xona
C = [5, 200, 2500, 9.0, 3] ← Villa, 5 xona
cos(θ) = A · B |A| × |B| = Σ Aᵢ × Bᵢ √(ΣAᵢ²) × √(ΣBᵢ²)
1.0 = to'liq o'xshash · 0.0 = umuman o'xshash emas
Hisoblash misoli
A·B = 2×2 + 65×70 + 650×680 + 8.5×8 + 3×3
    = 4 + 4550 + 442000 + 68 + 9
    = 446,631
|A| = √(4+4225+422500+72.25+9) = √426810 ≈ 653.3
|B| = √(4+4900+462400+64+9) = √467377 ≈ 683.7
cos(A,B) = 446631 / (653.3 × 683.7)
cos(A,B) ≈ 0.999 → Juda o'xshash! ✅
cos(A,C) ≈ 0.612 → Kam o'xshash ✗
📌 Natija
Foydalanuvchi Yunusobod 2-xonali uyni ko'rsa — tizim cosine similarity > 0.85 bo'lgan boshqa uylarni "O'xshash e'lonlar" sifatida ko'rsatadi. Bu tranzaksiya ehtimolini +34% oshiradi.
❌ Boshqa saytlar
Hech qanday tavsiya tizimi yo'q. Foydalanuvchi o'zi qidiradi.
✅ Mulkchi
Matematikaga asoslangan tavsiya — foydalanuvchi ko'proq uy ko'radi.

Bron narxi:
Dinamik narx formulasi

Uy ijara narxi kunlik, haftalik yoki oylik bo'lishi mumkin. Chegirmalar, kafolat puli va bron muddati hisobga olinadi. Bu formula to'liq avtomatik ishlaydi.

TotalPrice = (DailyRate × N) × (1 − D) + SecurityDeposit
N = kun soni | D = chegirma koeffitsienti (0–1)
D = {
  0.10  agar N ≥ 7 (haftalik)
  0.20  agar N ≥ 30 (oylik)
  0     agar N < 7 (kunlik)
Uzoq muddat = katta chegirma — bozorni rag'batlantiradi
📐 Misol: 45 kunlik ijara
DailyRate = 650,000/30 ≈ 21,667 so'm/kun
N = 45 kun → D = 0.20 (20% chegirma)
SecurityDeposit = 650,000 so'm
──────────────────────────────────────
Total = (21,667 × 45) × (1 − 0.20) + 650,000
      = 975,000 × 0.80 + 650,000
Total = 1,430,000 so'm

JWT Token:
HMAC-SHA256 imzolash

Tizimga kirish uchun foydalanuvchi parol bilan autentifikatsiya qiladi. Keyin har bir so'rovda JWT token tekshiriladi. Token soxta bo'lishi matematik jihatdan imkonsiz.

JWT = Base64(header) . Base64(payload) . HMAC-SHA256(secret, header.payload)
Imzo = secret kalit bilmay yasab bo'lmaydi
Parol saqlash: hash = BCrypt(password, salt, cost=12)
Parol hech qachon ochiq saqlanmaydi — faqat hash
1
Login: BCrypt tekshiruvi
BCrypt.Verify(kiritilgan_parol, saqlangan_hash) → true/false
2
Access Token (15 daqiqa)
HMAC-SHA256 bilan imzolangan JWT. Foydalanuvchi ID, role, IsVerified ma'lumotlari
3
Refresh Token (7 kun)
Access token tugaganda, Refresh token bilan yangi token olinadi — qayta login kerak emas
BCrypt - nima uchun MD5/SHA1 emas?
Algoritm1 hash vaqtiBrute-force xavfi
MD5~1 nsJuda yuqori ⚠️
SHA-256~10 nsYuqori ⚠️
BCrypt (cost=12)~250 msJuda past ✅
Brute-force vaqt: T = 2bits GPU_speed × thash

Real-time Chat:
WebSocket Protokoli

Oddiy HTTP so'rov — faqat bir yo'nalishda. Har xabar uchun yangi ulanish — O(n) overhead. WebSocket — doimiy ikki yo'nalishli aloqa.

HTTP vs WebSocket taqqoslash
❌ Oddiy HTTP (polling)
Har 2 soniyada yangi so'rov → Keraksiz yuklanish. Latency: ~200-500ms. Server resurslarini isrof qiladi.
✅ WebSocket (SignalR)
Bir marta ulanish → xabarlar darhol yetadi. Latency: <50ms. Server resurslarini tejaydi.
HTTP overhead: O(n) = n × (header_size + RTT)
WebSocket overhead: O(n) = handshake + n × 2 bytes
n = xabarlar soni | 1000 ta xabar uchun: HTTP ~1MB vs WS ~2KB
WebSocket Handshake jarayoni
1
HTTP Upgrade so'rovi
Client: GET /hub/chat HTTP/1.1 → Upgrade: websocket, Sec-WebSocket-Key: [base64]
2
Server kalitni hisoblaydi
Accept-key = Base64(SHA1(client_key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"))
3
101 Switching Protocols
Server 101 status bilan javob qaytaradi → Doimiy ulanish o'rnatildi
4
Ikki yo'nalishli uzatish
Server → Client: yangi xabar, bron holati, bildirishnoma — darhol, 0 ms kechikish
